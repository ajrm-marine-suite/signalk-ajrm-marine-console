AJRM Marine Help

Onboard reference for the AJRM Marine sailing workflows and safety logic.

Alpha Release disclaimer: This software is Alpha Release and has not been tested in live environments and must not be relied upon for navigation or safety. The Authors do not accept any responsibility for loss or damage as a result of using this software.

AJRM Marine is designed to keep the important traffic information visible and audible without creating unnecessary alarm fatigue. This is the onboard reference for the main sailing workflows and safety logic.

Setting up AJRM Marine for the first time

Work through these steps in order. You do not need to fill every configuration box: the suite starts with sensible defaults and optional instruments remain blank when the boat does not supply that data. The aim is first to prove that Signal K has trustworthy boat data, then select any ambiguous sources, and finally test the complete suite.

1. Install the suite

In Signal K Admin, open App Store, install AJRM Marine Suite, enable it under Server > Plugin Config, and restart Signal K after the first installation. The installation should include Display, Traffic, Notifications, Audio, Voyages (Capture), Navigation Integrity, Locations, Tidal Database, and Weather Database. Notifications works in the background and therefore has no separate top-menu page.

Why: these packages form one chain. Traffic makes the safety decision, Notifications manages the event, Audio delivers speech, Display shows it, Capture records the evidence, Locations owns spatial records, and Tidal Database owns predictions, and Weather Database owns provider forecasts and offline caches. A missing link can leave apparently unrelated features unavailable.

If it is wrong: Overview shows a core app as missing, or BITE reports a required plugin as not installed, disabled, not visible, or without backend status. Install or update that named package, enable it, restart Signal K, hard refresh the browser, and rerun that BITE group.

2. Get the boat data into Signal K

Configure the Signal K input plugin or NMEA gateway suitable for the boat. AJRM Marine is not tied to a particular gateway brand or source name. With the equipment switched on, open Data > Data Browser and confirm that the live values make sense. A basic installation normally needs:

  • navigation.position — latitude and longitude.
  • navigation.courseOverGroundTrue — direction of travel.
  • navigation.speedOverGround — speed over the ground.
  • AIS targets under vessels.* for Traffic.
  • Heading, depth, wind, speed through water, rudder angle, temperature, and other paths only when those sensors are fitted.

Why: the suite cannot repair absent or nonsensical sensor data. Position, COG, and SOG establish own vessel motion; AIS establishes the surrounding traffic.

If it is wrong: own vessel is absent or stationary on the map, Navigation Integrity reports missing or stale GPS, Traffic cannot calculate CPA/TCPA, or an instrument remains null. Check that the sensor and gateway are powered, that their Signal K input connection is enabled, and that Data Browser shows a fresh timestamp. Correct the input at source rather than substituting COG for heading or inventing a value in AJRM Marine.

3. Identify the boat

In Signal K, set the self-vessel name, MMSI when applicable, length, beam, draft, and AIS antenna position when known. Then review Traffic's own-vessel size category and the Harbour, Coastal, Offshore, and Anchored profiles.

Why: Traffic uses vessel dimensions for hull-aware closest approach, while the profiles decide the CPA/TCPA limits and announcement cadence appropriate to the situation.

If it is wrong: the self-vessel popup shows unknown dimensions, CPA is calculated using conservative assumptions, or alerts feel too early or too late. Correct the vessel data and profile settings; do not tune thresholds merely to hide bad source data.

4. Check Navigation Integrity

Open Navigation Integrity and inspect its Navigation Reference status. With one coherent GNSS source, automatic selection should normally choose position, COG, and SOG. If several receivers or compasses are present, use the exact source IDs shown there in the preferred-source settings. Deliberately select a magnetic compass or autopilot heading source before it is treated as bow heading. COG is direction of travel, not compass heading.

If it is wrong: the boat outline points in the direction of travel instead of the bow, Heading is null, the selected source changes unexpectedly, or DR lacks a heading/STW vector. Select the intended physical source, check its freshness, and remove obsolete preferred-source IDs. If the sensor supplies magnetic heading only, complete the Derived Data step below.

5. Configure Derived Data without creating loops

Install SK Derived Data (signalk-derived-data) from the App Store when standard calculated navigation paths are needed by AJRM Instruments or other Signal K clients. Navigation Integrity calculates its own qualified navigation reference, but other clients may expect the standard navigation.headingTrue and navigation.magneticVariation paths.

Open Server > Plugin Config > Derived Data and start with:

  • Magnetic Variation: enabled.
  • True Heading: enabled only when the boat supplies magnetic heading but not direct true heading.
  • Magnetic Course Over Ground: disabled.
  • True Course Over Ground: disabled when the receiver already publishes navigation.courseOverGroundTrue. Enable it only when magnetic COG is the sole COG input.
  • Set and Drift: disabled.
  • Estimated steer error and direction: disabled unless another client specifically requires that Direct-To display aid.

Use Data > Source Priority for a path-level choice when more than one source publishes the same value. Prefer the maintained Derived Data WMM source for navigation.magneticVariation, but keep direct physical sensors preferred for COG and true heading.

Typical Derived Data mistakes and corrections:

  • Heading is null although magnetic heading exists: enable True Heading, confirm magnetic variation is available, and check that the physical magnetic-heading source is selected in Navigation Integrity.
  • Heading jumps or uses the wrong source: direct and calculated true heading may be competing. Prefer the calibrated physical true-heading source and disable the redundant True Heading calculation.
  • COG sources compete or appear circular: do not enable both magnetic-to-true and true-to-magnetic COG calculations. Prefer direct true COG when the receiver supplies it.
  • DR current disagrees or seems self-referential: disable Derived Data Set and Drift. Navigation Integrity must use its explicit, qualified current evidence instead.
  • True and magnetic values differ by an implausible angle: inspect all sources for navigation.magneticVariation and give the WMM source path-level priority over an old receiver value.

BITE checks the resulting AJRM navigation and instrument contracts, but it cannot prove that every Derived Data choice is correct for the hardware. Always compare the selected sources and headings with the real instruments.

6. Add charts

For local charts, install Charts Provider Simple (signalk-charts-provider-simple). In Server > Plugin Config > Charts Provider Simple, set the chart directory (default ~/.signalk/charts-simple), enable the plugin, and restart Signal K after the first installation. Put existing MBTiles there or use Manage Charts. Subdirectories become groups that can be enabled or disabled, including nested groups.

Serving existing MBTiles requires no container runtime. Conversion requires signalk-container and a working Docker or Podman runtime. In Display, Navigation Integrity, Voyage Review, and Locations, select Auto Charts and enable the required folders.

If it is wrong: only the basemap appears, Auto Charts lists no charts, or folders are missing. Confirm the provider is enabled, its directory is correct, the files are valid MBTiles, the relevant folders are enabled, and Manage Charts lists them as available. BITE cannot judge whether the correct chart is visibly aligned; pan and zoom over a known area as a manual check.

7. Choose and test an audio output

Open Audio, choose at least one output, and run Sound Check. Audio shows whether Piper, its voice, FFmpeg, the Pi speaker, browser output, stream, and Desktop Player are ready. Use Audio to install the Player on a supported Mac, Windows, or Linux browser device. Pi Controller can install Piper on supported Raspberry Pi systems; a Pi speaker also needs a working ALSA output.

If it is wrong: BITE reports renderer or output-route failure, Audio shows a selected route as unavailable, or Sound Check is silent. Install the dependency named by Audio, select an available route, check mute and volume, then repeat Sound Check before rerunning BITE.

On an iPhone or iPad, Safari requires a user gesture before sound can start and iOS may suspend it when the screen locks, the browser is backgrounded, or another app takes audio focus. Silent mode, volume, and site permissions can also prevent speech. The installable Player is for desktop operating systems, not iOS. For iOS background or lock-screen listening, open the MP3 stream URL shown by Audio in a radio/player app that supports background playback. Test it before departure and do not assume foreground Safari audio will provide unattended safety announcements.

8. Add only the optional features needed
  • Instruments provides graphical instruments and configurable alerts. Enable only instruments backed by useful paths on the boat.
  • Vessel Database retains names, dimensions, notes, import/export, and online enrichment. Traffic works without it, but identification and speech improve with it.
  • Snapshot and Simulator support diagnosis and testing.
  • Locations stores versioned positions and geometry for anchorages, tidal ports, gates, named weather forecast points and hazards. Tidal Database owns prediction providers, secondary-port corrections and the offline tide cache; configure the UKHO key and correct subscription tier there. Weather Database owns weather providers, provider-separated offline caches, freshness and source selection; Open-Meteo is enabled by default. Create or edit dedicated forecast points in the Weather workspace in Locations, or select any stored port, marina, anchorage, mooring or tidal gate. Inspect and refresh its forecast in Weather Database. Planning then provides Gate Passage and Anchor Force views without storing another provider key, tide cache or weather cache. Treat these as planning aids and verify their inputs against current official sources and observed conditions.
  • Pi Controller provides Raspberry Pi health, controlled shutdown, and optional Piper installation.

A BITE test for an intentionally uninstalled optional package is not the same as a core failure. Install it only if that feature is wanted; if installed, it should be enabled and its own tests should pass.

9. Run BITE before relying on the suite

Open BITE in Console and choose Run all tests. BITE checks the installed package chain, contracts, alert lifecycle, Traffic decisions, Audio delivery, Capture/review, Navigation Integrity, and installed optional packages. It creates synthetic situations and records a BITE voyage so a failure can be reviewed later. Some safety tests deliberately take time to reach a stable result; wait for the group to finish rather than treating a running test as failed.

Run BITE only in a safe test state. Stop the Simulator and do not mix BITE with a fresh live navigation or instrument feed. The opening isolation check deliberately refuses to inject synthetic vessel data into an active feed. On a boat, run it dockside with the relevant inputs safely isolated; never run synthetic collision tests while voyaging.

A complete pass means the software chain behaved correctly under the test conditions. You must also hear the final spoken summary on the output you intend to use. BITE can prove that Audio requested and processed speech, but only a person can confirm that the speaker, tablet, or Player was actually audible.

How to respond to common BITE failures:

  • Required plugin or backend status: install or update the named core package, enable it, restart Signal K, hard refresh, and rerun the failed group.
  • Safety isolation: stop Simulator and remove or disable the fresh live input before trying again. This failure is protective, not evidence that collision logic is broken.
  • Navigation/GPS/DR: check the live paths and timestamps in Data Browser, then inspect Navigation Integrity's selected sources and preferred-source settings.
  • Audio renderer or output: use Audio's readiness details and Sound Check; install Piper/FFmpeg or Player as appropriate and select a usable route.
  • Traffic, Notifications, or collision chain: make sure all core packages are current compatible versions, sound policy is explicit, then restart and rerun. Do not weaken alert thresholds to make the test pass.
  • Capture or completed voyage: enable Capture, check that its voyage directory is writable and has free disk space, and allow finalisation to complete.
  • Optional package: enable/update it if the feature is wanted, or leave it uninstalled if it is not.

After correcting a failure, rerun the failed test first and then Run all tests. Before departure, also perform the manual checks BITE cannot make: compare heading with the real compass, confirm own vessel is correctly placed and orientated, zoom over a known chart, and physically hear Sound Check and the BITE summary.

Overview

AJRM Marine Display keeps the chart, target list, alert panel, profile controls, settings, and Help interface focused on sailing use. AJRM Marine Traffic supplies target safety state, CPA/TCPA and profile decisions; AJRM Marine Notifications supplies alert lifecycle and priority.

The map remains usable if GPS is unavailable. In that state the Display keeps chart browsing available and visibly reports the AJRM Marine Traffic or Signal K data-health state.

Alerts

AJRM Marine Display uses AJRM Marine Traffic and Notifications server-generated alert events for chart colouring, the bottom alert panel, optional popups, Signal K notifications, and sound outputs. The browser, audio plugin, and companion displays do not decide alert severity themselves; they display and speak the event that the provider has already classified.

Console's built-in Alerts tab provides a focused read-only list of active and recent events. It uses the same Notifications projection and never creates or speaks a second alert.

  • Normal: no attention required.
  • Alert / Watch: a target worth watching, normally visual-only unless sound has been enabled for that state.
  • Traffic advisory: relevant traffic inside the active profile's advisory CPA/TCPA limits. It is the lower audible traffic state.
  • Collision alarm: traffic inside the active profile's danger CPA/TCPA limits, or another high-priority collision condition. This needs more urgent attention.
  • Emergency: distress AIS traffic, such as AIS SART, MOB, or EPIRB targets. Emergency does not depend on CPA/TCPA and is sorted above ordinary traffic alarms.

Repeat timing is controlled by the active profile's repeat sensitivity and the configured repeat intervals. A target that escalates to a higher state can be announced immediately, even if the previous state was recently spoken. The default repeat intervals are 3 minutes for Alert/Watch and Traffic advisory, 1 minute for Collision alarm, and 30 seconds for Emergency before profile repeat sensitivity is applied.

How encounter announcements are built

AJRM Marine builds spoken encounter messages server-side and sends the same wording to the chart, alert panel, Signal K notifications, browser speech, AJRM Marine Audio, and companion displays. The message is intended to explain why the target needs attention, not to replace the skipper's judgement.

  • Severity first: Traffic advisory means the target is inside the active profile's advisory CPA/TCPA limits. Collision alarm means the target is inside the danger limits, or another high-priority collision condition is present.
  • Speed thresholds: CPA/TCPA alert speed checks use the faster of own-vessel SOG and target SOG, so a stationary vessel outside a harbour can still become a collision alarm when own vessel is closing on it.
  • Where to look: clock position is based on the target's current relative bearing from own vessel heading or course.
  • What kind of vessel: AJRM Marine uses AIS name, class, length, and speed where available. Stationary vessels outside harbours are announced as stationary; stationary vessels inside known harbour regions are ignored for encounter alerts.
  • What is happening: closest-approach geometry is described as a prediction: CPA will be on your port side, on your starboard side, ahead, or astern. On the same general course, AJRM Marine says You are overtaking it only when own vessel is faster and the target is ahead or abeam. It says It is overtaking you only when the target is faster and astern or abeam. Otherwise it says Same general course. Stationary targets use You will pass wording because they cannot pass own vessel.
  • How close and when: CPA and TCPA describe the expected closest approach. With hull-aware CPA enabled, AJRM Marine uses vessel dimensions and AIS antenna offsets where available, and a conservative hull envelope when they are missing.
How the geometry wording is chosen
Action prompt sectors

Based on the target's current bearing relative to own vessel. Used only for moving collision-level targets.

Port-bow head-on: alter starboard Starboard sector: Give Way Port and astern sectors: Stand On Stationary collision target: pass well clear
CPA pass wording

Based on where the target is predicted to be at closest approach, relative to own vessel's course.

Ahead: CPA will be ahead Astern: CPA will be astern Starboard: CPA will be on your starboard side Port: CPA will be on your port side
When alerts are suppressed

Suppression is also decided by the server, so all connected displays see the same result.

  • Own vessel: excluded from traffic alerts, even if it appears in the AIS target list. AJRM Marine uses it only as the reference for relative bearing, CPA, TCPA, and profile logic.
  • Base stations and AtoNs: AIS base stations and aids to navigation are classified as non-collision targets and do not create CPA encounter alerts.
  • Out of range: targets outside the configured maximum target range are ignored for active encounter alerts. If a previously active target becomes range-ignored, AJRM Marine publishes a clear event so alert panels and companion displays can remove it.
  • Stationary in harbour: stationary vessels inside known harbour regions are ignored for encounter alerts, even when own vessel is outside the harbour. This prevents anchored, moored, or berthed harbour traffic from being announced as a live collision risk while passing the harbour entrance.
  • Stationary outside harbour: stationary vessels outside known harbour regions are still eligible for alerts. Their announcements include stationary and say You will pass it to port, You will pass it to starboard, You will pass ahead of it, or You will pass astern of it.
  • Silenced or muted: silencing a target or muting sound suppresses speech, not awareness. The target remains visible on the chart and in lists.
Collision avoidance prompt
Important — limited avoidance guidance: Head-on, Give Way, Stand On, overtaking, and other avoidance prompts are useful indications based on the limited AIS, heading, CPA, and TCPA information available to AJRM Marine. They are not advice or a determination under the International Regulations for Preventing Collisions at Sea (COLREGs). The suite does not have every input needed to make that decision—for example, it may not know whether your vessel is sailing or motoring, whether the vessels are in sight of one another, the other vessel's operational status, visibility, sea room, or local navigation constraints. The skipper remains responsible for assessing the complete situation, applying the COLREGs, and deciding and carrying out the appropriate safe action.

Action prompt wording is added only to collision-level alerts where CPA geometry indicates collision or close quarters. If the projected geometry predicts a defined pass to port, starboard, ahead, or astern, AJRM Marine reports that CPA geometry and CPA/TCPA without advising a manoeuvre. Traffic advisories do not get Stand On, Give Way, alter-starboard, or pass-well-clear prompts.

  • Alter course early to pass well clear is used for stationary collision targets. AJRM Marine does not apply head-on, give-way, or stand-on wording to stationary targets because they are not crossing under power.
  • Head-on: alter starboard, pass port-to-port is used for moving targets only when the target is dead ahead or on the port bow, from 345 degrees through 360 degrees relative.
  • Give Way is used for collision-level targets in the starboard sector, from just over dead ahead through 112.5 degrees relative.
  • Stand On is used for collision-level targets in the astern or red/port sector, from more than 112.5 degrees through less than 345 degrees relative.

The alter-starboard wording is deliberately narrow. AJRM Marine does not use it for a target already on the starboard bow, because turning further starboard could increase risk if the vessel is expected to pass safely to starboard. Always use the full situation, including visibility, sea room, other traffic, and vessel constraints, before making a manoeuvre.

Lost GPS is treated as a system alert. It repeats every three minutes while GPS remains unavailable unless paused, and the pause is cleared automatically when GPS is received again.

Silencing

Silence all stops current active traffic alerts from speaking without hiding them from the chart. Individual targets can also be silenced from the target list. Silenced vessels remain visible and are marked on the chart and in the list, so the skipper can still see what has been quietened.

Silencing is server-authoritative, so all connected browser clients and companion displays read the same state after refreshing their server data.

Profiles

Profiles hold the CPA/TCPA limits, vessel-size adjustments, and speed thresholds used by AJRM Marine Traffic. Display can select the active AJRM Marine Traffic profile when commands are available. Threshold editing belongs to the AJRM Marine Traffic administration web app.

Automatic profile selection is provided by AJRM Marine Traffic when enabled. Manual profile selection remains available from Display.

Charts

Auto Charts chooses a local Signal K chart provider layer for the current map position and zoom. Basemaps are separate background layers; OpenSeaMap is a transparent seamark overlay and should sit above charts so wind farms, buoys, and other seamarks remain visible.

Expand Chart folders beneath Auto Charts to enable or disable complete Charts Provider Simple directory trees. Nested folders inherit a disabled parent. When charts overlap, use the Cycle chart icon or the configured keyboard key (C by default). Hover or focus any map icon to see its function; Display, Navigation Integrity, Voyage Review, and Locations share this convention.

Manual panning pauses own-vessel following. Press the centre vessel button to recentre on your vessel and resume automatic following.

HTTPS and iPhone Trust

AJRM Marine webapps and the Signal K Admin UI are served by the same Signal K server. Certificate warnings must therefore be fixed at the Signal K server hostname, not inside each webapp.

  1. Give the Raspberry Pi a stable boat-network name, for example boat-pi.local, and preferably a fixed LAN IP address.
  2. Install mkcert on the Pi or another trusted computer and create a local certificate authority.
  3. Generate a certificate for every name used to open Signal K, for example boat-pi.local, boat-pi, and the Pi IP address.
  4. Copy the generated certificate to ~/.signalk/ssl-cert.pem and the private key to ~/.signalk/ssl-key.pem on the Pi. Both files must be readable only by the Signal K user.
  5. Ensure the systemd service starts Signal K with SSLPORT=3443, then restart Signal K.
  6. Install the mkcert root CA on the iPhone. Open the CA file on the iPhone, install the profile in Settings, then enable full trust in Settings > General > About > Certificate Trust Settings.

After that, open Signal K using the same hostname that is in the certificate, for example https://boat-pi.local:3443/signalk.

Debugging a Problem

After updating AJRM Marine, the browser can keep an old JavaScript or CSS file in its cache. If the server has been updated but the chart, settings, badge, or help text still looks unchanged, do a hard refresh before assuming the plugin is still wrong.

  • Chrome, Edge, or Firefox on Windows/Linux: press Ctrl+F5 or Ctrl+Shift+R.
  • Chrome, Edge, Firefox, or Safari on Mac: press Cmd+Shift+R. In Safari, Option+Cmd+R also reloads the page from the network.
  • Safari on iPhone or iPad: tap reload first. If the old page remains, clear the site data in Settings > Safari > Advanced > Website Data, search for the Signal K hostname such as boat-pi.local, delete that entry, then reopen AJRM Marine.
  • iPad with a hardware keyboard: Cmd+Shift+R can be used in many browsers. If it still shows old behaviour, clear Safari website data for the Signal K hostname.
  • Installed Home Screen webapp: close the webapp from the app switcher after clearing site data, then open it again from the Home Screen.

If a hard refresh does not change the behaviour, check the Signal K plugin version, then capture a fresh AJRM Marine snapshot so the browser state and server state can be compared.

Suite Architecture

AJRM Marine is a suite of cooperating Signal K plugins, not one large application. Backend plugins calculate and publish authoritative state; frontends render that state and send explicit user actions.

  • Traffic owns AIS CPA/TCPA, encounter wording, profiles, voyage state, and traffic audio policy.
  • Notifications owns active/recent alert projection, lifecycle, priority, and deduplication.
  • Audio owns the audible timeline and renders the spoken announcements used by server speaker, stream, browser, and desktop-player outputs.
  • Voyages (Capture) and Snapshot provide recording, replay, diagnostic evidence, and voyage review.
  • Navigation Integrity and its DR Plotter publish and render navigation-integrity, dead-reckoning, and plotted fix state.
  • Location Editor is the sole spatial catalogue and owns location names, types, geometry, revisions, anchoring attributes, profile areas, and named weather forecast coordinates. Ports, anchorages, moorings and tidal gates can also be used directly as forecast coordinates.
  • Tidal Database and Weather Database independently own their providers and durable offline caches. Weather Database resolves its selectable forecast places through Locations. Display and Marine Planning consume those services rather than fetching or caching provider data themselves.
  • Marine Planning is a read-only consumer of Locations, Tidal Database, Weather Database, and live Signal K values.
  • BITE exercises installed plugins through their public Signal K/API surfaces and records evidence through Capture.

The canonical architecture documents live in the public AJRM Marine Architecture repository: github.com/ajrm-marine-suite/ajrm-marine-architecture.

npm run build:web:recovered
